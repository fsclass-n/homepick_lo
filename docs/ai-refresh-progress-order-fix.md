## 증상

재학습은 성공했지만 진행 단계 표시가
준비 → 공공데이터 크롤링 → 데이터 전처리 → **다시 공공데이터 크롤링** → **서버 반영으로 점프** → 완료 순서로 보임.

## 원인 (화면 표시 문제)

1. **뒤로 감**: GitHub API 의 단계 상태는 즉시 일관되게 갱신되지 않아, 이미 끝난 단계(크롤링)가 잠깐 '진행 중'으로 다시 보고될 수 있음.
   기존 코드는 받은 단계를 그대로 표시해서 화면이 이전 단계로 되돌아감.
2. **점프**: 전처리·학습·반영이 합쳐 약 9초로 끝나는데, 화면 확인 주기가 최대 20초(브라우저 10초 + 서버 캐시 10초)라 중간 단계를 볼 틈 없이 '서버 반영'으로 넘어감.
3. 단계 전환 순간(진행 중인 단계가 없을 때)에는 '준비 중'으로 판단되는 문제도 있었음.

## 수정 내용

| 구분 | 변경 |
|---|---|
| 화면(JS) | 지금까지 표시한 가장 먼 단계를 기억하고 **앞으로만 이동** (`shownStep`) |
| 화면(JS) | 진행 상태 확인 주기 10초 → **5초** |
| 서버 | 상태 캐시 10초 → **4초** |
| 서버 | 진행 중인 단계가 없으면 **마지막 완료 단계의 다음 단계**로 판단 (가장 많이 진행된 단계 기준) |

- 건너뛴 단계는 다음 단계로 넘어갈 때 자동으로 완료(✓) 표시
- 매우 짧은 단계(1~7초)는 여전히 화면에 잠깐 보이지 않을 수 있으나, 순서가 뒤바뀌지는 않음

## 검증

- 실제 단계 기록을 GitHub API 로 확인 (순서·소요 시간 정상)
- 받은 상태 순서 `설치 → 크롤링 → 전처리 → 크롤링(지연된 정보) → 서버 반영 → 완료` 를 재현한 시뮬레이션에서
  화면이 `준비 → 크롤링 → 전처리 → 전처리(유지) → 서버 반영 → 완료` 로 앞으로만 이동함을 확인
- Java 컴파일, JS 문법 검사 통과
