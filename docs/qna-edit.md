# Q&A 게시판 글 수정

## 규칙

| 항목 | 내용 |
|---|---|
| 권한 | **본인 글**(`writer_id` = 로그인 아이디)만 |
| 시점 | **답변이 등록되기 전**까지만 — 답변 후 질문이 바뀌면 답변과 맞지 않게 되므로 |
| 바꿀 수 있는 것 | 제목, 내용 (작성자 이름 · 작성일 · 상태는 그대로) |
| 입력 검사 | 글쓰기와 같음 (제목 100자, 내용 2,000자, 앞뒤 공백 제거, 줄바꿈 1자) |
| 예전 글 24건 | 작성자 아이디가 없어 수정 불가 |

## 화면

- 상세 보기 하단: 본인 글 · 답변 전이면 **수정** 버튼 (삭제 · 글쓰기 옆)
- 수정 화면: 글쓰기 화면을 수정 모드로 사용 — 「질문 수정하기」, 기존 제목 · 내용이 채워짐, 「(작성자는 바꿀 수 없습니다)」, **취소**(상세로) · **수정하기**
- 저장하면 그 글 상세로 돌아와 「글이 수정되었습니다.」, 보던 목록 페이지 · 검색 조건도 유지

## 처리 (`GET/POST /qna/{번호}/edit`)

| 경우 | 동작 |
|---|---|
| 본인 · 답변 전 | 수정 화면 / 저장 → 상세 + 안내 |
| 입력 오류 | 수정 화면에 오류, 입력값 유지 |
| 다른 회원 · 예전 글 | 상세 + 「본인이 작성한 글만 수정할 수 있습니다.」 |
| 답변이 달린 글 | 상세 + 「답변이 등록된 글은 수정할 수 없습니다.」 |
| 비로그인 | 로그인 → 로그인 후 수정 화면으로 복귀 |
| 없는 글 | 목록 + 안내 |

- 저장 SQL 에서도 `WHERE id = ? AND writer_id = ? AND answer IS NULL` 로 다시 확인 → 화면을 연 뒤 관리자가 답변을 달아도 수정되지 않음
- 화면 표시(버튼)와 서버 확인을 공통 메서드(`checkEditable`)로 처리

## 검증 (`./gradlew test` 39개 통과)

| 테스트 | 확인 내용 |
|---|---|
| 수정 버튼 | 본인 · 답변 전에만 (다른 회원 · 비로그인 · 답변 달린 글에는 없음) |
| 수정 화면 | 기존 내용, 수정 모드 문구, 폼 주소, 목록 상태 hidden 값, 취소 → 상세 |
| 본인 수정 | 제목 · 내용 저장(공백 · 줄바꿈 정리), 작성자 이름 유지, 상세(목록 상태 유지)로 이동 |
| 입력 오류 | 수정 화면 + 오류 + 입력 유지, 저장 안 됨 |
| 다른 회원 · 답변 달린 글 · 예전 글 · 비로그인 · 없는 글 | 모두 저장 안 됨 + 각 안내 / 로그인 후 수정 화면 복귀 |

- 테스트는 롤백되어 실제 DB 그대로 (qna 24건)
