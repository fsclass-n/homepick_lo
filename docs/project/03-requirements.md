## 3-1. 기능 요구사항

### 회원 (MEM)

| ID | 요구사항 | 상세 내용 | 우선순위 | 상태 |
|---|---|---|---|---|
| MEM-01 | 약관 동의 | 필수 2개(이용약관 · 개인정보) + 선택 2개. "전체 동의" 체크 시 4개 모두 체크 · 해제, 개별 4개 모두 체크 시 전체 동의 자동 체크. 필수 미동의 시 다음 버튼 비활성 | 상 | ✅ |
| MEM-02 | 기본 정보 입력 | 이름 2자 이상, 생년월일 8자리(YYYYMMDD), 성별(M/F) 선택 | 상 | ✅ |
| MEM-03 | 휴대폰 본인인증 | Firebase reCAPTCHA + SMS 인증번호 6자리, 3분 타이머, 재발송. 인증 성공 시 `firebaseUid` 발급 | 상 | ✅ |
| MEM-04 | 계정 정보 입력 | 아이디 4~20자 영문·숫자·_, 비밀번호 영문+숫자 포함 8~30자, 비밀번호 확인 일치 | 상 | ✅ |
| MEM-05 | 회원가입 처리 | 서버에서 같은 규칙으로 재검증, 아이디 중복 시 409, 비밀번호 BCrypt 암호화 저장 | 상 | ✅ |
| MEM-06 | 아이디 로그인 | 아이디 · 비밀번호 BCrypt 검증, 성공 시 세션(`loginUser`)에 아이디 · 이름 저장 | 상 | ✅ |
| MEM-07 | 아이디 저장 | 로그인 화면 "아이디 저장" 체크 시 브라우저에 아이디 보관 | 하 | 🟡 |
| MEM-08 | 소셜 로그인 | 카카오 · 네이버 · 구글 OAuth2. 처음이면 자동 회원가입, 기존 회원이면 이름 · 이메일 갱신 | 상 | ✅ |
| MEM-09 | 로그아웃 | 세션 삭제 후 메인으로 이동 | 상 | ✅ |
| MEM-10 | 아이디 · 비밀번호 찾기 | 로그인 화면 링크 | 하 | 🟡 |

### AI 실거래 단지 추천 (AI)

| ID | 요구사항 | 상세 내용 | 우선순위 | 상태 |
|---|---|---|---|---|
| AI-01 | 조건 입력 | 최대 예산(만원, 1 이상), 희망 방 수(1~4방+), 희망 지역(필수) | 상 | ✅ |
| AI-02 | 단지 추천 | 지역 일치 → 예산 이하 · 방 수 일치 단지를 점수 순 정렬. 점수 = 조건 근접도 50% + 저평가 35% + 최근 거래 15% | 상 | ✅ |
| AI-03 | 추천 근거 표시 | 실거래 중위가, 최근 거래일, 거래 건수, AI 적정가 대비 저평가 정도, "AI가 학습한 결과" 문장 | 상 | ✅ |
| AI-04 | 로그인 전용 | 비로그인 시 추천 · 재학습 불가, 로그인 안내 표시. 재학습 API는 401 반환 | 상 | ✅ |
| AI-05 | 시장 인사이트 | 시장 요약 지표, 월별 거래량 · 중위가, 가격 결정 요인, 시·군·구 평당가 순위, 단지 유형, 저평가 TOP 5. 수도권/서울/인천/경기 탭 | 중 | ✅ |
| AI-06 | 실거래 명시 | "현재 판매 중인 매물이 아닌 거래 완료 기록"임을 화면에 표시 | 상 | ✅ |
| AI-07 | AI 재학습 | 버튼 클릭 → GitHub Actions에서 크롤링 · 전처리 · 학습 → 결과 JSON 커밋 → 서버 반영 | 상 | ✅ |
| AI-08 | 진행 상태 표시 | 준비 → 크롤링 → 전처리 → 학습 → 서버 반영 → 완료. 경과 시간, 단계가 뒤로 가지 않음, 실패 시 실패 단계와 원인 표시 | 중 | ✅ |
| AI-09 | 중복 실행 방지 | 10분 내 재요청 차단, 실행 중이면 차단, 35분 넘게 진행 중이면 실패 처리 | 중 | ✅ |

## 3-2. 비기능 요구사항

| ID | 구분 | 요구사항 | 구현 |
|---|---|---|---|
| NFR-01 | 보안 | 비밀번호는 평문 저장 금지 | BCrypt 해시 (`password_hash`) |
| NFR-02 | 보안 | API 키 · DB 비밀번호를 코드에 넣지 않음 | `.env` · Render 환경변수 · GitHub Secrets, `.gitignore` 로 제외 |
| NFR-03 | 보안 | 본인 확인된 휴대폰으로만 가입 | Firebase Phone Auth `firebaseUid` 필수 |
| NFR-04 | 성능 | AI 재학습이 수 분 안에 끝나야 함 | 병렬 크롤링: 크롤링 27초, 전체 약 2분 30초 |
| NFR-05 | 성능 | 2MB 학습 데이터 전송량 감소 | gzip 응답 압축, 서버 메모리 캐시(30분) |
| NFR-06 | 가용성 | GitHub 접속 실패 시에도 추천 가능 | jar 에 포함된 `apartments.json` 으로 대체 |
| NFR-07 | 배포 | main 에 push 하면 자동 배포 | Render 자동 배포, GitHub Actions → EC2 SSH 배포 |
| NFR-08 | 사용성 | PC · 모바일 모두 사용 가능 | Bootstrap 5 반응형, 모바일 레이아웃 별도 확인 |
| NFR-09 | 신뢰성 | 실거래와 매물을 혼동하지 않게 함 | 화면 전체에 "실거래 · 거래 완료 기록" 표기 |
| NFR-10 | 운영 | 실패 원인을 바로 알 수 있어야 함 | 서버 터미널 · 화면에 실패 단계와 원인, Actions 로그 링크 출력 |
