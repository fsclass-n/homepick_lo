## 1. 로그인한 경우에만 사용

| 기능 | 변경 전 | 변경 후 |
|---|---|---|
| AI 단지 추천 받기 | 비로그인도 추천 결과 표시 | 비로그인 시 '추천 단지' 탭에 "로그인 후 이용할 수 있습니다 · 로그인하기" 안내 |
| 최신 데이터로 AI 재학습 | 버튼은 로그인 시에만 표시, API 401 (이미 제한됨) | 동일 |
| 재학습 진행 표시 | **비로그인에게도 표시** (다른 사람이 실행한 작업이 보여 "로그인 안 했는데 된다"처럼 보임) | 로그인 사용자에게만 표시 |
| 안내 문구 | 로그인하면 재학습할 수 있어요 | 🔒 AI 단지 추천과 AI 재학습은 로그인 후 이용할 수 있어요 |
| 시장 인사이트 | 공개 | 공개 (변경 없음) |

- 서버가 템플릿에 `data-logged-in`(세션 `loginUser` 유무)을 넣고 JS 가 확인
- 참고: 추천 계산은 브라우저에서 공개 데이터(`/api/ai-data/apartments`, 인사이트와 공용)로 하므로 화면 제한임.
  서버에서 강제하려면 추천 계산을 서버 API 로 옮기거나 데이터 API 를 로그인 전용으로 바꿔야 함(이 경우 인사이트도 로그인 전용이 됨)

## 2. EC2·Render 가 함께 학습되는 이유 (정상 동작)

- 두 서버 모두 같은 GitHub 저장소의 **하나의 워크플로(ai-data-refresh.yml)** 를 실행하고,
  학습 결과도 같은 `apartments.json`(GitHub main)을 받아 씀
- 따라서 어느 도메인에서 재학습해도 결과는 두 도메인에 함께 반영되고, 진행 상태도 같은 작업을 보여줌
- 비로그인 사용자에게는 이제 진행 표시가 보이지 않음

### 해결

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 요청 방식 | 순차 1건씩 | **동시 8건 병렬** (`CRAWL_WORKERS`, 일 호출 한도는 횟수 기준이라 영향 없음) |
| 세션 | 전역 1개 | 스레드별 세션 (스레드 안전) |
| 재시도 | 최대 4회, 2·4·8·16초 대기 | 최대 3회, 1·2·4초 대기 |
| 진행 로그 | 지역별 출력 | `[완료/전체]` 진행률 + 총 소요 시간 |
| 크롤링 단계 제한 | 없음 (작업 전체 45분) | **20분**, 작업 전체 30분 |
| 서버의 지연 판단 | 60분 | 35분 |
| 화면 안내 | 약 7~10분 | 보통 3~5분 (API 가 느린 날은 더 걸릴 수 있음) |

- 로컬 측정: 83건(1개월분) **6초** (순차일 때 수 분)
